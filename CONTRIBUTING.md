# Contributing to vPole

## Contributor License Agreement

Before your first contribution can be merged, you must accept the
[vPole Individual Contributor License Agreement](CLA.md). You keep the copyright in your work; the
agreement licenses your contributions to the maintainer so vPole can be offered under the
GNU Affero General Public License v3.0 and under commercial licenses.

When you open your first pull request, the CLA bot asks you to accept the agreement through your
GitHub account. The pull request cannot be merged until you accept. You only need to accept once
for each CLA version.

## License

vPole is licensed under the [GNU Affero General Public License v3.0 only](LICENSE.txt). By submitting a
contribution, you confirm that you have the right to submit it under the terms of the CLA. If a
contribution includes code you did not write, including AI-generated code that may reproduce
third-party material, identify its source and license in the pull request.

## Workflow

- Fork the repository (or use a branch if you have write access) and open a pull request against
  `master`.
- Keep history linear with concise conventional-style commit subjects.
- Follow [AGENTS.md](AGENTS.md) and the guides in [docs](docs/README.md).
- Run the verification described in AGENTS.md before requesting review.
- Never commit secrets; keep local credentials in ignored local settings or environment variables.

## Reporting security issues

Do not report vulnerabilities in public issues. Follow [SECURITY.md](SECURITY.md).
